# 第 17 轮 · 窄屏展开态详情卡压到 34vh（P4-11）

## 本轮目标

第 16 轮把手机的详情卡改成「默认收起」（高 78px），但点「展开」后卡片仍占 366×371（390×844 下 y 348–719），地图可用带只剩 273px，「边看图边读情节」依然做不到。本轮把展开态也压下去，并让超出部分在卡内滚动。

判据（BACKLOG P4-11 原文）：390×844 展开态 `#detail` 高 ≤ 300；正文可滚；可见标签 ≥ 20；1440 行为不变。

## 改了什么

只动了一处 CSS —— `assets/css/style.css` 的 `@media (max-width: 620px)` 块，紧接 `.detail:not(.expanded) .d-chapter` 之后：

```css
/* 展开态也别把地图吃掉一半：44vh（844 高下 371px）压到 34vh（约 287px），
   卡本来就 overflow:auto，正文与翻页键在卡内滚。腾出的这一段留给地图与标签。 */
.detail.expanded { max-height: 34vh; }
```

没有改 JS，也没有改收起态的任何规则：

- 收起的机制（`S.detailExpanded` / `.expand` 键 / `syncExpanded()` / 三处复位）沿用第 16 轮，本轮不碰，避免把「收起」和「展开高度」两件事搅在一起。
- `.detail` 的基础样式本来就是 `overflow: auto`（`assets/css/style.css:511`），所以压高度后卡内滚动是现成的，不需要新加 `overflow`。
- 只在 620 断点内写，1440 / 1200 / 800 / 640 全部不受影响（下方有实测）。

## 为什么是 34vh，而不是改 `44vh` 本身

- `44vh` 同时也是 620–900 段的继承值（第 5 轮为让出时间轴而设，`.` detail` 的 `max-height: 44vh` 在 620 断点里也写着）。直接改它会把 640–900 段一起动，而那段是否要收起还没定（BACKLOG P4-12 待做，640×844 实测卡片 388px、可见标签只有 12 条）。
- 写 `.detail.expanded` 是更高优先级的独立规则，只覆盖窄屏展开态，回退时删一行即可。

## 为什么不做「只让正文滚、头部吸顶」

试想过 `.detail.expanded .d-head { position: sticky; top: 0 }` 配 `.d-body { overflow-y: auto }`，放弃的理由：

1. `.detail` 自己就是滚动容器（`overflow: auto`），再套一层滚动会让「滚到哪了」在两处状态之间不一致，手机上尤其容易拖着拖着卡住。
2. `.d-head` 的 `padding-top` 来自 `.detail` 的 `padding: 22px 24px 18px`，sticky 贴到滚动口上缘时会跟 padding 打架，需要额外负 margin 兜，属于为一个 287px 的卡片引入新的对齐风险。
3. 卡内只有「回目 + 站名」在两屏高度里必然可见（滚到底也只剩 297px 行程），吸顶收益小。

判断：**先用最小改动把高度拿下来**，吸顶留作以后的观感优化。

## 回滚方法

前进式回退，记为 `U-018-01（回退 U-017-01）`：

1. 删掉 `assets/css/style.css` 620 断点内 `.detail.expanded { max-height: 34vh; }` 那一行（含上方两行注释）。
2. 验收：390×844 展开态 `#detail` 高度回到 **371**、卡顶 348、可用带 273；收起态仍是 78（不受影响）。
3. 其余文件无需改动 —— 本轮只碰了这一个 CSS 规则。

## 遗留问题

- **只能滚整张卡**：回目与站名会随正文滚走；要头部常驻需再做吸顶（本轮已论证为什么先不做）。
- **展开态仍占 287px**：相对 371 已好，但 390×844 下地图可用带 305px 仍偏窄；再往下压到 28vh（约 236px）会让正文一屏只剩两行，收益可能为负，未做。
- **620–900 段仍走整卡**：640×844 实测 388px、可见标签 12 条，比 390 收起态更差 —— 已立 P4-12，本轮未动。
- 卡内滚动条在 iOS 上是否可见未测（`scrollbar-width: thin` 只对支持该属性的浏览器生效），标**待核**。
