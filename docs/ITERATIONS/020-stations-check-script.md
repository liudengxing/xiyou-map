## 本轮目标

## 改了什么

新增 `scripts/check-stations.mjs`（156 行 / 8017 B，无 npm 依赖，`node scripts/check-stations.mjs` 直接跑），四段检查：

1. **规模**：站点 48、`chapters` 101 项（0 为空占位）且 1–100 回回目非空、`nan` 81 条。
2. **难号与回目**：每站 `nan` 都在 1–81 且不重复挂两站、1–81 逐条都有站；每站 `chapter` 是 `[from, to]` 且 1 ≤ from ≤ to ≤ 100；经纬度存在并落在图幅 `lon [50,140] / lat [-5,50]`；西行段回目起点沿站序**单调不减**（这是第 3 轮「等距取靠后一站」的前提，破了就得重看那个取舍）。
3. **分类**：按 `modern` 分五桶（判定顺序即优先级）。
4. **与文案比对**：从 `index.html` 抠 `<b>N站</b>` 三段中文数字（`cnToNum` 处理十 / 百），与实际分档逐个比；再校验「三段 + 灵山 1 = 48」与虚构占比 ≥ 80%。

## 为什么这么写

- **判定顺序不能颠倒**：`西梁女国` 的 `modern` 是「小说虚构 · 一说今新疆库车一带」——它含「今」，但必须归虚构。所以顺序是 `小说虚拟` → `虚构` → `小说地名/无确指/示意位置` → `今/多比定` → 其余（另有出典）。之前心算时就是被这个「一说今」绊过。
- **从页面抠数字，而不是在脚本里再写一份常量**：文案是给人看的、脚本是给文案把关的。脚本里再写一遍 8/15/24 就变成「两个常量互相对」，永远测不出文案改错。代价是脚本依赖 `index.html` 里 `<b>八站</b>` 这种写法，所以找不到三段时给的是明确错误（「没找到三段 `<b>N站</b>` 的文案（找到 0 段），无法比对」）而不是静默通过。
- **数据从 `data.js` 现算**：`new Function("window", src + ";return window.XIYOU_DATA;")({})` —— 与页面的 `window.XIYOU_DATA` 同一份源，不复制数据。
- **「另有出典」硬校验 1 站且必须是灵山**：这一桶是兜底桶，将来谁把某站的 `modern` 写成认不出的字样，会立刻掉进这里被抓住，而不是被算进「小说地名」蒙混过关。

## 遗留问题

- 分类只靠 `modern` 的**字面关键词**，词一改（比如把「小说虚构」写成「虚构」）就会换桶 —— 这既是它的灵敏度也是它的脆弱处。若将来要更稳，应给 `data.js` 加显式 `kind` 字段，脚本只读该字段；本轮不动数据模型（越界）。
- 文案里「八站」后面那串括号点名的地名（长安、法门寺……）没有逐一对账，只对数字；把括号里的名单也校验需要把文案拆成结构化列表，成本和收益不成比例。
- 仍未接 CI（项目无 `package.json`），两条校验都是手工命令；`scripts/` 下的两个脚本没有共同的入口，将来可以合成 `node scripts/check-all.mjs`。
- 「花果山」「天竺国」的比定本身有异说（一说 / 后世多比定），已在文案里写明，属「待核」而非本脚本能判的事。
