# 第 3 轮 · P2-2 回目直达（搜「27」跳白虎岭）

> 时间：2026-11-26 18:44　改动单元：U-003-01　耗时约 25 分钟（超预算 10 分钟，因为中途补了越界提示与解析重构）

## 本轮目标

BACKLOG P2-2：搜索框输入 `27` 或 `第二十七回` 能直接跳到该回对应的站点；该回没有独立站点时，也要给出「最近为哪一站」的提示，而不是「无此名目」。

选它的理由：协议里「100 回目录可检索并跳转到站」是 P2 明文要求，而此前 `doSearch` 只做子串匹配 —— 搜「27」匹配不到任何站名（数据里没有「27」这个字面），等于 100 回目只可读不可达。15 分钟量级，收尾干净。

## 改了什么

### `assets/js/app.js`（+85 行，1031 → 1115 行）

1. **`CN_DIGIT` + `cnToNum(s)`**（放在 `stationByNan` 之后）：汉字数字转整。支持零〇一二两三四五六七八九十百，处理「十」在首（十二）、「十」在尾（二十）、「十」在中（二十七）三种位置，以及「百」（一百）。只覆盖 1–100 这一实际取值范围，不做通用大数解析。
2. **`parseChapterQuery(q)`**：判定输入是不是「回目号」。
   - 先 `q.replace(/\s+/g, "")`，容忍「第 27 回」中间的空格。
   - `/^第?(\d{1,3})回?$/` 命中 → 返回数字。
   - `/^第?([零〇一二两三四五六七八九十百]{1,6})回?$/` 命中 → `cnToNum`。
   - 返回值三态：**数字 = 有效回目号；`NaN` = 看着像回目号但越界（0、101）；`null` = 不是回目号**。三态是为了把「回目号应在 1–100 之间」和「无此名目」两种提示分开 —— 第一版把越界也返回 `null`，导致输 `101` 得到「无此名目」，语义错了。
3. **`stationByChapter(ch)`**：按 `chapter: [from, to]` 区间反查站点。
   - 精确命中 → `{ idx, exact: true }`。
   - 落在空档（第 8–11 回、第 14–26 回等多处无独立站点）→ 取区间距离最小者，`{ idx, exact: false, gap }`。
   - **距离相等时取靠后的一站**（`if (d <= bestD)`），理由是章节在推进，「即将到达的那一站」比「刚离开的那一站」更符合直觉。第 8 回因此落到天庭（[4,7]）而不是别的站。
4. **`doSearch(q)` 开头插入回目分支**：`chq != null` 时优先于关键字匹配 —— 因为 `27` 这类输入不可能匹配到站名，抢先判定不会误伤；而 `火焰` 走不到这个分支（正则不匹配）。
5. **抽出 `bindSearchResult(box)`**：原来点击绑定内联在 `doSearch` 末尾，回目分支需要复用时抽成函数，两处调用。
6. **`chapterTitle(ch)` 用于结果行标题**：显示完整回目（如「尸魔三戏唐三藏　圣僧恨逐美猴王」），副标题才是 `第 27 回 · 白虎岭` —— 先给回目再给落点，符合「按回目找」的意图。

### `index.html`

- `#q` 的 `placeholder` 由「搜地名 · 妖怪 · 回目」改为「搜地名 · 妖怪 · 回目 / 输回目号直达」，把新能力写进可发现的位置（不用改工具栏加按钮）。

## 为什么这么改（设计取舍）

- **不走工具栏加按钮**：100 个回目做成按钮或列表会把工具栏撑爆，也与「工具栏是图层开关」的语义冲突。搜索框已经是「去哪」的入口，把回目号塞进同一个入口最省交互成本。
- **不做「回目 → 站点」的预计算映射表**：`stationByChapter` 现算，48 站遍历代价可忽略，且 `data.js` 改站点区间后不用同步维护第二张表（避免两处真相）。
- **空档给「最近一站」而不是报错**：第 8–11 回（观音访僧、太宗还魂、刘全进瓜）本来就没有独立站点，直接说「无此名目」会让用户以为站点数据缺了；说明「此回无独立站点，最近为天庭」既诚实又给了去处。
- **等距取靠后**：见上，是「即将到达」的直觉，也保证第 8 回落到天庭而不是在 [4,7] 与 [12,13] 之间来回跳。
