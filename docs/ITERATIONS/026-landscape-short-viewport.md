# 026 · 手机横屏（640×360）把浮层叠到一起

## 本轮目标
BACKLOG 已无未勾选项，取 STATE「下一轮候选」里的 **640×360 横屏可用性实测**。
判据先写死：① 五个浮层（工具栏 / 随行条 / 搜索框 / 详情卡 / 时间轴）两两不重叠；
② 搜索框底到详情卡顶之间留出连续地图带；③ 收起态卡片仍只露「回目 + 站名」；
④ 三档已有视口（390 / 640 / 1440）不回归。

## 改了什么
`assets/css/style.css` 新增一个矮屏断点（放在 `@media (max-width: 620px)` 之前，确保在 900 断点之后生效）：

```css
/* ≤480 高（手机横屏，如 640×360）：横铺抽屉与 118px 的时间轴把竖屏那套堆叠挤爆了——
   640×360 实测「随行」条 top 152 与详情卡 top 157 直接叠在一起。这里只做「让开」：
   时间轴压到 84px、卡片底边抬到 96px、「随行」条挪到搜索框之上，腾出连续可用的地图带。 */
@media (max-height: 480px) {
  .timeline { height: 84px; padding: 6px 12px 8px; }
  .detail { bottom: 96px; }
  /* 40vh = 144px 时展开态顶到 y120，会压住搜索框（底 139）；30vh = 108px，顶到 y156。 */
  .detail.expanded { max-height: 30vh; }
  .chars { top: 68px; padding: 4px 8px; }
  .chars-hint { display: none; }
}
```

没有动 JS、没有动 900 / 620 两个断点里的任何声明 —— 竖屏那套堆叠在 844 高下本来就成立。

## 为什么这么改
- **问题不是「小屏」，是「矮屏」**：900 断点把卡片放到底部、`bottom:130px` 给时间轴让路，这个布局假设视口有 700+ 高。360 高时「随行」条（900 断点写死 `top:152px`）正好落在卡片顶（157）上方 5px 处 —— 两者直接叠 31px。
- 让所在的三处都跟「时间轴有多高」有关：时间轴 118 → 84，卡片底边 130 → 96，随行条从 `top:152` 挪到 `top:68`（工具栏底 64 与搜索框顶 108 之间那条缝）。
- 展开态单独压到 30vh：40vh 在 360 高下是 144px，卡顶会顶到 y120 压住搜索框（底 139）；30vh=108px 顶到 156，与搜索框留 17px。
- 没有把 `.chars` 在矮屏直接藏掉：点人走线是协议里的三条交互主线之一，横屏手机上也该能点。

## 顺手查了、没改的
「八十一难」抽屉在 640×360 下是 372×360：`#drawer-nan` 的 `scrollHeight = 360 = clientHeight`（自己不滚），真正可滚的是它的 `.drawer-body`（`scrollHeight 1694 / clientHeight 307`）。但实测有矛盾：把 `.drawer-body.scrollTop` 设到 1387（到底）后，末格 `.nan-cell` 的 `getBoundingClientRect().top` 仍是 459、`.nan-foot` 底边 672 仍超出 360 —— **无法据此判断末格到底能不能滚到**，所以本轮不动它，见 BACKLOG P4-21（待核）。

顺带回退：本轮曾试 `.drawer { overflow-y: auto }` + `.drawer-head { position: sticky }`，实测抽屉自身 `scrollHeight` 仍 360（滚动发生在外层 body 里），属无效果的猜测，且 sticky 头写了个非调色板的 `#f7eedb`，已整段回退。

## 回滚方法
删除 `assets/css/style.css` 里 `@media (max-height: 480px) { … }` 整段（5 条声明 + 两段注释，位于 `@media (max-width: 620px)` 之前）。
验证已恢复：640×360 下 `.chars` 回到 `top 152`、与详情卡叠 31px；1440 / 390 两档不受影响（断点不命中）。

## 遗留
1. 640×360 下的地图带只有 52px —— 还能再挤：搜索框可并进工具栏、随行条可缩成图标。属观感/信息密度，另立条目。
2. 抽屉在 480 高以下的可滚动性待核（P4-21），需要一个更可靠的判据（`scrollIntoView` 后看 `elementFromPoint`，而不是读 rect）。
3. 648×360 这类「宽 620–900、矮 360–480」的组合本轮只测了 640×360 一个点。
