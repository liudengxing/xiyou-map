# 第 23 轮 · 收起态难号徽标的对比度量化（P4-17）

## 本轮目标

第 19 轮加的徽标（`第 47 – 49 难`）是 11px 朱砂字 + `rgba(176,58,46,.42)` 边框，压在宣纸底与详情卡渐变上。观感够，但从没算过 —— 本轮把 WCAG 对比度算出来，不达标就改，并把算法固化成脚本。

判据（写在动手前，避免事后编标准）：
- **文字** ≥ 4.5:1（WCAG 1.4.3 AA，11px 常规字重按「正文」算），
- **边框** ≥ 3:1（WCAG 1.4.11「非文本对比度」，边框是徽标的视觉边界）。
- 两档都要在**徽标可能落到的每一种底色**上达标，取最差。

## 关键认识：徽标底下不是一种颜色

翻样式表才看清：`.detail` 的底色是 `linear-gradient(180deg, rgba(249,242,226,.97), rgba(244,235,214,.97))` 叠在 `--paper #f3e7cd` 上，展开态还有一块实色 sticky 卡头 `#f9f2e2`。所以「底色」至少有四种：
纸底 `(243,231,205)`、卡顶 `(249,242,225)`、卡底 `(244,235,214)`、吸顶卡头 `(249,242,226)`。
只拿 `--paper` 算会漏掉更亮的面（更亮 → 文字对比度更高但有例外），只拿卡顶算会漏掉更暗的面（更暗 → **对比度更低**，卡底才是最差一侧）。

## 算出来的数（脚本 `scripts/check-contrast.mjs` 的输出）

| 底色 | 文字（原 `.42` 边框） | 边框（原 `.42`） | 边框（新 `.8`） |
| --- | --- | --- | --- |
| 纸底 `--paper` | 4.91:1 | **1.87:1** | 3.54:1 |
| 卡顶渐变 | 5.39:1 | **1.92:1** | 3.78:1 |
| 卡底渐变 | 5.07:1 | **1.89:1** | 3.63:1 |
| 吸顶卡头 | 5.39:1 | **1.92:1** | 3.79:1 |

结论：**文字本就达标**（最差 4.91:1），**边框全线不达标**（1.87–1.92:1，只有要求的六成）。所以只改边框，不动字色 —— 把 `--cinnabar` 换成更深的 `--cinnabar-deep` 虽然能到 6.89，但那会改掉徽标的观感，而这枚字只是「小注」，4.91 已经够。

## 改了什么

`assets/css/style.css`（1230 行 / 35400 B → 1233 行 / 35692 B），`@media (max-width: 900px)` 里 `.detail:not(.expanded) .d-nanbadge`：

```css
/* 边框同时是这枚徽标的「边界」——WCAG 1.4.11 要求非文本 UI 元素对底色 ≥3:1。
   原先 0.42 叠在纸上只有 1.87:1（看着像虚线影子）；0.8 最差一侧 3.63:1 达标。
   改样式后跑 `node scripts/check-contrast.mjs` 复核。 */
border: 1px solid rgba(176, 58, 46, 0.8);
```

新增 `scripts/check-contrast.mjs`（123 行 / 5112 B，无 npm 依赖）：

- 从 `assets/css/style.css` **现读** `--paper`、徽标的 `color` 与 `border` 的 rgba、详情卡渐变两端的色值与 alpha、吸顶卡头的实色 —— 脚本里不复制一份常量，改了样式再跑就会跟着变（与 `check-stations.mjs` 抠「关于」数字的做法同一条原则）。
- 用 WCAG 相对亮度公式（`srgb → 线性`、`0.2126/0.7152/0.0722`）算对比度；边框先按 alpha 合成到底色上再算（页面就是这么渲染的）。
- 四种底色逐一输出，取最差：文字 < 4.5 或 边框 < 3 就 `exit 1`，并打印是哪一项、差多少。
- 为什么把阈值写成常量而不是参数：这两个数是 WCAG 的固定门槛，允许传参等于允许「这次先放过」。

## 回滚方法（前向）

用户说「撤销 U-023」时：把 `assets/css/style.css` 里那行改回 `border: 1px solid rgba(176, 58, 46, 0.42);`（注释一并删掉），
`node scripts/check-contrast.mjs` 应当重新报 `边框对比度最差 1.87:1`、`exit=1` —— 这就是「已恢复」的判据。
记为 `U-024-01（回退 U-023-01）`；`scripts/check-contrast.mjs` 可保留（它此时正好用来证明回到了不达标状态）。

## 遗留问题

- 只量了比色，没量**观感**：边框 0.8 比原先「实」，若以后觉得抢眼，可在 3:1 以上继续微调（0.7 时卡底 3.06:1，只余 0.06 的余量，不建议）。
- 同页还有别的 `rgba(176,58,46,0.28–0.45)` 边框（`.d-nan .n`、`.tag.hot`、`.search-results button`、`.d-nav button:hover` 等），本轮**没动**——它们是文案旁的次要框，且不在「必须可辨的控件边界」清单里；若要全站达标，需要逐条定级，属新条目。
- 未跑真实读屏器/高对比模式（`forced-colors`），标「待核」。
