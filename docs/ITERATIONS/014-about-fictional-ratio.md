## 数字是怎么算的（口径与命令）

按 `data.js` 里每站的 `modern` 字段分类，用 node 现算（`new Function("window", src)` 加载 `window.XIYOU_DATA`）：

```
A 虚构境域  4   方寸山、东海、幽冥界、天庭          （modern 含「小说虚拟」）
B 虚构国度 11   宝象、乌鸡、车迟、西梁女、祭赛、朱紫、比丘、灭法、凤仙、玉华、金平
                                                     （modern 含「虚构」，即「小说虚构」「小说虚构·一说今新疆库车一带」）
C 小说地名 24   双叉岭、两界山、鹰愁涧、黑风山、高老庄、黄风岭、流沙河、五庄观、白虎岭、
                平顶山、号山、黑水河、金兜山、琵琶洞、真假美猴王、荆棘岭、小雷音寺、稀柿衕、
                盘丝洞、黄花观、狮驼国、镇海寺、隐雾山、铜台府   （modern 含「小说地名／示意位置／无确指」）
D 今地可考  8   花果山、长安、法门寺、巩州、河州卫、通天河、火焰山、天竺国   （modern 含「今」）
E 另有出典  1   灵山                                （modern = 「天竺 · 灵鹫山（小说中的大雷音寺）」）
合计 48；A+B+C = 39，占 81.3% ⇒ 文案写「八成以上」
```

第一次起草时写成「四十八站里…剩下**二十五站**…六成以上」，是心算把 E（灵山）并进了 C 又漏算了一档；
跑上面的脚本核出 `A+B=15 / C=24 / D=8 / E=1`，改成「二十四站…余下灵山另有出典…八成以上」。
**这一步是本轮唯一有价值的教训：文案里的数字必须跑脚本，不能心算。**

## 为什么这么写

- **并列列举站名**：只给百分比读者无从核对，把每一档的站名列出来，「八站」「十五站」「二十四站」都能在图上数出来。
- **花果山、天竺国单独加括号说明**：这两站是「后世多比定／小说中的西天佛国」，说成「对上了实地」会过强；
  加一句「后两站只是『后世多比定』，不是说书人写明的」，既不削弱论点的量级，也不把话说满。
- **灵山不并进任何一档**：它是全书终点，`modern` 写的是「天竺 · 灵鹫山（小说中的大雷音寺）」，
  既不是纯虚构也不像长安那样可考，单列一句「另有出典」比硬塞更诚实。
- **不改 `data.js` 的 `modern` 字段**：这几个字段是详情卡在用的（读者点开某一站就看到），措辞已经够细；
  本轮只加一段汇总文案，不动既有文案，回滚面最小。

## 遗留问题

- 分类口径写在 `docs` 与页面上，但**没有脚本固化**：下次改 `modern` 字段，这些数字不会自动更新。
  若要彻底防漂移，可仿第 12 轮的 `check-seamarks.mjs` 加一个 `scripts/check-about-stats.mjs`，
  把 `data.js` 的分类结果与 `index.html` 里的三处 `<b>` 数字比对，不一致就非零退出。属可选增强，未立条。
