## 本轮目标

BACKLOG 的 P3-2：海洋纹样从 20 簇加到 32 簇，让南海与阿拉伯海不再显得空，同时不压海岸线与陆地注记。

判据（写死在开工前，避免事后找理由）：
1. `g.sea-mark path` 数量 = 簇数 × 2（每簇两行波浪），从 40 变 64；
2. **所有簇的经纬点必须落在水面上**（这是本轮新引入的硬判据）；
3. 1440 / 1200 / 390 三档标签度量不回归（`visible` 不减少、`overlapPairs=0`、`pinBite=0`）；
4. 无横向溢出、控制台无报错。

绘制部分只动了两处数值，都带注释说明动机：

```js
// 行距与弧宽按序号轻微错开，避免 32 簇排成整齐网格
for (var r = 0; r <= 1; r++) {
  var w = (11.2 - r * 2.0 + (si % 2) * 0.8) * U;
  var yy = q[1] + r * (6.4 + (si % 3) * 0.5) * U;
  ...
}
```

原来的 `w = (11.2 - r * 2.0) * U`、`yy = q[1] + r * 6.4 * U` 是等距的，20 簇时看不出问题，32 簇就会排成整齐网格（像印刷网点，不像手绘水纹）。加 `(si % 2) * 0.8` 与 `(si % 3) * 0.5` 两个抖动项后，弧宽在 11.2/10.4 em 之间、行距在 6.4/6.9/7.4 em 之间微变。

## 为什么这么改

- **为什么加「水面校验」这条判据**：手写经纬点很容易落在岛上。第一版 32 点里就有两个落陆地——`[120.6, 22.4]` 在台湾岛上、`[108.6, 12.6]` 在越南沿海。这两个水纹会直接压在陆地上，看起来像地图画错了。校验方法见下。
- **为什么不在局部放大**：加密是全域的均匀提升，不针对某个海域单独堆点，否则 1440 宽下会出现「南海很密、东海很空」的新问题。
- **为什么不改 `.sea-mark` 的样式**：第 3 轮调过 `stroke: rgba(63,107,138,.24)` / `stroke-width: calc(0.9px * var(--u,1))`，实测在当前密度下刚好（再深会抢路线，再浅看不见）。本轮只动数据与几何，不动样式，避免两个变量同时变而无法归因。

## 验证证据

### 水面校验（本轮新增的手法，可复用）

在 iframe 里注入脚本，用项目自带的 Natural Earth 110m 陆地轮廓做点面判断，不依赖任何外部服务：

```js
const w = document.querySelector("#f").contentWindow;
const t = await w.fetch("/assets/vendor/land-110m.json").then(r => r.json());
const geo = w.topojson.feature(t, t.objects[Object.keys(t.objects)[0]]);
const onLand = seaMarks.filter(p => w.d3.geoContains(geo, p));
```

## 踩到的坑（写下来给后面几轮）

**`bcdp_navigate` 打开带 `?t=<新值>` 的包装页不一定真的重新加载。** 第一次截图上 `g.sea-mark path` 仍是 40，说明拿到的是旧页面。可靠做法：先用 `bcdp_js` 把 `f.src` 设成 `/index.html?t=` + `Date.now()` + `#s=5`，`bcdp_wait` 3000ms 以上，再用**数量断言**（`g.sea-mark path` 的个数）确认新代码已生效，最后才截图。看截图不看数字，会被 stale 帧骗。

另：`bcdp_cdp` 的 `Page.captureScreenshot` 又吐了一次巨型 base64（382698 字节，溢出到 `Z:\BUILD-~1\dsh-spill-2zAofO\session-060b269d6922\117693cdb1af-bcdp_cdp.txt`）。截图统一用 `bcdp_screenshot({selector:"#f"})`。

## 回滚方法

前向回退，下一轮记为 `U-009-01（回退 U-008-01）`：

1. `assets/js/app.js` 的 `seaMarks` 删掉新增的 12 个点，恢复成 20 点（东海 5、南海 4、孟加拉湾 4、阿拉伯海 3、补充 4）；
2. 绘制循环里把 `w` 改回 `(11.2 - r * 2.0) * U`、`yy` 改回 `q[1] + r * 6.4 * U`，删掉两个抖动项与那条注释；
3. 恢复验证：1440 下 `g.sea-mark path` 数量回到 **40**；三档 `overlapPairs=0` / `pinBite=0` 仍成立。

## 遗留问题

- 水纹是手工经纬点，加密靠人挑位置。若以后要覆盖更大海域（如日本海、红海），建议把「点在水面上」这一步做成构建期脚本（`scripts/check-seamarks.mjs`），而不是每轮在浏览器里临时注入——本轮为控制时间盒没做，记入 BACKLOG 候选。
- 水纹密度只有两档（20 / 32 簇），没有随视口宽度变化。窄屏 390 下 32 簇里可见的只有南海那几片，属于正常（地图本身被裁）。
